# BookOasis 3D 서재 가이드

BookOasis 서재를 모던 서점 건물로 지어 걸어 다니며 둘러보는 화면입니다(사이드바 **BookOasis 3D 서재**, 주소 `/library3d`).
세션(일반·성인·오디오북·비디오)마다 한 층, 보관함마다 서가 구역, 작품마다 책장의 책(표지)으로 진열하고, 그 자리에서 읽거나 BookOasis 화면으로 넘어갈 수 있습니다.

## 1. 켜기

`.env`에 아래를 넣고 다시 시작합니다. 기본값은 꺼짐(`false`)입니다.

```env
LIB3D_ENABLED=true

# BookOasis DB (3D 서재가 보관함·작품 목록을 여기서 읽는다) - {db_type}은 세션 이름으로 바뀐다
BOOKOASIS_DB_URL=mysql://bookoasis:비밀번호@192.168.0.31:3306/bookoasis_{db_type}
#  SQLite면: BOOKOASIS_DB_URL=sqlite:////BookOasis경로/db/{db_type}.db
BOOKOASIS_DB_TYPES=general,adult,audiobook,video

# BookOasis 주소 (표지 /covers/… 와 작품 상세·BookOasis 뷰어 링크)
BOOKOASIS_URL=http://127.0.0.1:5930
# 위 주소가 서버 안에서만 통하면, 브라우저가 여는 주소를 따로
LIB3D_PUBLIC_URL=http://192.168.0.10:5930
```

```bash
cd /mnt/bookoasis_assistant && git pull && systemctl restart bookoasis_assistant
# 도커: cd /opt/bookoasis_assistant && git pull && docker compose up -d --build
```

사이드바에 **BookOasis 3D 서재**가 생기고, 그 아래 **둘러보기 · 설정 · 인물 수 · 창밖 풍경 · 3D 모형 · AI 설정** 메뉴가 나옵니다.

### 요구 사항
- **BookOasis DB에 읽기 접근**이 필요합니다. MariaDB/MySQL은 `PyMySQL` 패키지(`requirements.txt`에 포함), SQLite는 같은 서버에서 파일을 읽을 수 있어야 합니다.
- **서재 안에서 읽기**(자체 뷰어)는 BookOasis DB의 `books.file_path` 경로 그대로 파일을 엽니다. 이 프로그램이 BookOasis와 **같은 경로로 책 파일을 볼 수 있어야** 합니다(같은 서버·같은 마운트, 도커면 같은 경로로 볼륨 연결). 경로가 다르면 "BookOasis 뷰어로 읽기"를 쓰세요.
- 브라우저는 WebGL이 되는 최신 브라우저(크롬·엣지·사파리·파이어폭스). 3D 라이브러리(three.js)와 사람·가구 모형은 인터넷(cdnjs·jsdelivr)에서 받습니다.

### 그 밖의 `.env` (보통 비워 둠)

| 키 | 기본 | 설명 |
|---|---|---|
| `LIB3D_PER_LIBRARY` | `300` | 보관함마다 책장에 놓을 최근 작품 수 (10~1500). 최근 작품부터 눈높이 표지 칸(구역마다 약 56자리)에 놓고, 나머지는 모든 책장의 책등 칸에 고르게 섞습니다(구역마다 약 1,600자리, 빈 자리는 누를 수 없는 장식 책). 많을수록 층을 여는 데 오래 걸리고 메모리를 더 씁니다 - 느리면 줄이세요 |
| `LIB3D_BOOK_URL` | (비움) | 작품 상세 주소를 다른 형식으로 (`{id}` `{library_id}` `{db_type}` `{series}` `{bookoasis}`) |
| `LIB3D_COVER_URL` | (비움) | BookOasis에 표지가 없을 때 쓸 표지 주소 형식 |

## 2. 둘러보기

- **이동**: W A S D · 방향키 (휴대폰은 화면 왼쪽 아래 조이스틱), **둘러보기**: 마우스 끌기 / 화면 밀기
- **층 이동**: 아래 [층] 버튼 또는 로비 왼쪽 벽의 엘리베이터를 누름. 1층 일반 · 2층 성인 · 3층 오디오북 · 4층 비디오 (고른 보관함이 있는 세션만)
- **지도**: 구역(보관함) 목록에서 눌러 바로 그 앞으로 이동. **입구로**: 처음 자리로
- **이어서 시작**: 나갔던 층·자리·방향을 이 브라우저에 기억해 다음에 그 자리에서 시작합니다(서가 배치가 바뀌어 그 자리가 건물 밖이면 입구). 입구에서 다시 시작하려면 [입구로].
- **책 누르기** → 작품 카드: **여기서 읽기**(만화·웹툰 zip/cbz·그림 폴더, epub, pdf - 펼친 책 모양에 책장 넘김, 만화는 오른쪽→왼쪽도, 읽던 곳은 이 브라우저에 기억) · **BookOasis 뷰어로 읽기**(키오스크 모드로 열었다가 돌아옴) · **작품 상세(BookOasis)**
- 입구 벽·안쪽 벽의 **표지 포스터**도 누르면 같은 작품 카드가 열립니다.
- 표지는 가까이 간 책부터 BookOasis에서 받아 옵니다(작게 줄여 `DATA_DIR/lib3d_covers`에 저장).

- **아이패드·폰(터치 화면)**: 오른쪽 아래 이동 버튼 - ↑(W) 앞, ↓(S) 뒤, ←(A)·→(D) 옆으로, ⟲·⟳ 돌기, » 누른 채로 달리기. 여러 손가락으로 같이 눌러도 됩니다. 화면을 끌면 둘러보기, 짧게 누르면 책·엘리베이터 고르기.
- **앉기**: 의자·소파·벤치를 누르거나(5m 안), 가까이(2m 안) 가면 아래에 생기는 [앉기]를 누르면 그 자리에 앉습니다. 눈높이가 낮아지고 의자가 보는 쪽을 봅니다. 앉아서도 둘러보기·돌기는 되고, 걷기(W·↑·이동 버튼)나 [일어나기]로 일어납니다. 함께 보는 사람 화면에는 앉은 모습으로 보이고, 손님이 앉아 있는 자리에는 앉을 수 없습니다. 브런치 낭독 코너 의자에 앉으면 낭독 패널이 열립니다.

## 3. 설정 (모두 `DATA_DIR/lib3d.json`에 저장, 저장하면 바로 반영)

| 메뉴 | 고르는 것 | lib3d.json 키 |
|---|---|---|
| **설정** | 보여 줄 보관함 (세션별 묶음 체크, [전부 보기]) - 고른 것이 없는 세션은 층이 없어짐 | `libraries` |
| **인물 수** | 층(열) × 인물 종류(행)마다 0~20명, 비우면 자동. 걷는·책 고르는·서서 읽는·벤치·대화(쌍) 손님, 안내 직원, 스톰트루퍼, 엘프, 숨은 인물 | `people` |
| **창밖 풍경** | 시간(자동·낮·노을·밤) · 계절(자동·봄·여름·가을·겨울) · 날씨(맑음·흐림·비·눈·자동). 자동은 브라우저 시계·지금 달·날마다 바뀌는 날씨 | `outside` |
| **창밖 풍경 > CRARES 현수막** | 없음 / **그림 주소**(jpg·png·gif·webp - 서버가 받아 `DATA_DIR/lib3d_banner.bin`에 두고 내려줌, 6시간마다 다시 받음, 15MB까지) / **보관함 표지**(고른 보관함의 최근 작품 표지가 정한 간격(기본 30초)마다 무작위로 바뀜, 서재에 숨긴 보관함도 고를 수 있음, 누르면 작품 카드). 오른쪽 창밖 (주)CRARES 건물 간판 아래 벽에 비율대로 걸림 | `banner`, `banner_lib`, `banner_sec` |
| **3D 모형** | 라운지 소파·의자, 화분, 바깥 차를 **지금 그대로**(코드로 그린 것, 가벼움) 또는 **3D 모형 파일**(처음 한 번 약 14MB, 그래픽 부담 큼) | `models` |
| **AI 설정** | 손님 대화·직원 응대·하루 호출 한도 (아래 5장) | `.env`의 `LIB3D_AI_*` |
| **AI 직원** | 사서·도슨트의 성격·업무·자율 업무 (아래 6장) | `lib3d_agents.json` |

3D 모형 파일 출처: GlamVelvetSofa·ChairDamaskPurplegold (© Wayfair, Eric Chadwick, CC BY 4.0), DiffuseTransmissionPlant (© Darmstadt Graphics Group, CC BY 4.0) - Khronos glTF Sample Assets / Ferrari 458 Italia (vicent091036, three.js 예제). 사람 모형은 three.js 예제의 Xbot·Michelle·readyplayer.me·스톰트루퍼·엘프를 씁니다.

## 4. 여러 사람이 쓰기 (관리자 · 관람자 · 함께 보기)

### 계정과 권한
사이드바 아래 [설정 > 사용자]에서 사람을 추가하고 권한을 고릅니다. 예전부터 있던 계정은 모두 관리자입니다.

| 권한 | 쓸 수 있는 것 |
|---|---|
| 관리자 | 모든 화면 (웹툰 다운로더·드라이브 감시·미니게임·3D 서재와 그 설정·사용자 관리) |
| 관람자 | **3D 서재 둘러보기·읽기·함께 보기만**. 로그인하면 바로 3D 서재로 가고, 다른 화면·설정·질문하기는 서버에서 막힘 (자기 비밀번호 변경·로그아웃은 가능) |
| 관람자 (성인 층 허용) | 위와 같고 2층 성인 서재도 보임. 허용하지 않은 관람자에게는 성인 층·표지·책 열기가 모두 막힘 |

- 관리자가 한 명은 남아야 하고, 자기 자신을 관람자로 내리거나 지울 수 없습니다.
- 3D 서재 설정(보관함·인물 수·창밖 풍경·3D 모형·현수막·AI)은 관리자만 바꾸며, 모두에게 같이 적용됩니다.
- 읽던 쪽·마지막 자리는 **사람마다** 따로 기억합니다(이 브라우저에, 계정별로).

### 함께 보기
같은 시간에 3D 서재에 들어온 사람끼리 서로 보입니다. 따로 켤 것은 없습니다.
- 같은 층의 다른 사람이 이름표를 단 사람 모형으로 걸어 다니고, 왼쪽 위에 "함께 보는 사람 N · 이름(층 · 읽는 중)"이 나옵니다.
- 왼쪽 아래 **채팅**: Enter로 보내면 모두에게 보이고, 같은 층 사람이면 그 사람 머리 위에 말풍선이 잠깐 뜹니다. 💬 버튼으로 접기. 층·지도 목록을 여는 동안은 숨겨집니다.
- **AI 직원 부르기**: 채팅창에 `@사서 질문`(또는 `@안내`·`@ai`·`@봇`), `@도슨트 할 말`(또는 `@가이드`) → 그 직원이 찾아보고 답합니다(자세한 것은 6장). 질문과 답은 **부른 사람에게만**(보라색 줄) 보이고, 직원이 소리 내어 한 말(`say`)만 같은 층 모두에게 보입니다. 관람자도 부를 수 있지만 서재 검색·무작위 책·시각·날씨만 쓰고, 성인 서재 권한이 없으면 성인 서재는 찾지 않습니다. 책을 찾은 답에는 **찾은 책 목록**(표지·제목·작가·권수·완결 여부, 최대 12개)이 붙고, 제목을 누르면 작품 카드(여기서 읽기·BookOasis 뷰어), ↗는 BookOasis 작품 상세를 새 탭으로 엽니다.
- 위치는 0.4초마다 서버와 주고받습니다(서버 메모리에만, 다시 시작하면 채팅도 비워짐). 몇 명~십여 명 규모에 맞춘 방식입니다.

## 5. AI: 손님 대화 · 질문하기 (선택)

[3D 서재 > AI 설정]에서 켭니다. 값은 `.env`에 저장됩니다(파일 권한 0600). 유료 API면 호출마다 요금이 듭니다.

| 항목 | `.env` 키 | 설명 |
|---|---|---|
| 연결 방식 | `LIB3D_AI_PROVIDER` | `openai`(기본) = OpenAI 호환 `/chat/completions` (LiteLLM·Ollama·LM Studio·OpenAI 등, 추가 패키지 없음) / `anthropic` = Claude API (`pip install anthropic` 필요) |
| API 주소 | `LIB3D_AI_BASE_URL` | OpenAI 호환일 때. 예 `http://192.168.0.26:4000/v1` (뒤에 `/chat/completions`를 붙여 부름) |
| API 키 | `LIB3D_AI_API_KEY` | anthropic에서 비우면 `ANTHROPIC_API_KEY` |
| 모델 | `LIB3D_AI_MODEL` | 게이트웨이에 등록된 이름 그대로 (예 `gemini-free3_1`). anthropic은 비우면 `claude-opus-5-5` |
| 하루 호출 한도 | `LIB3D_AI_DAILY` (기본 1000) | 손님 대화·직원 응대·자율 업무를 모두 합친 하루(서버 시각 자정 기준) LLM 호출 수. 도구를 쓰는 답 하나는 여러 번 부를 수 있음. 다 쓰면 다음 날까지 "오늘 AI 호출 한도" 안내로 멈춤. 0이면 한도 없음. [AI 설정]에 오늘 쓴 횟수가 나옴 |
| 손님 대화 | `LIB3D_AI_CHAT`, `LIB3D_AI_CHAT_SEC` | 층마다 두 손님이 무작위 책 한 권(제목·작가·장르·줄거리)을 두고 나누는 말을 말풍선으로. 간격(기본 60초)보다 자주 부르지 않고, 가까이 있고 탭이 보일 때만 부름 |
| AI 직원 응대 | `LIB3D_AI_ASK`, `LIB3D_MCP_COMMAND`, `LIB3D_MCP_SERVERS`, `LIB3D_AI_BUILTIN` | 채팅창에 `@사서 질문`·`@도슨트 할 말`을 쓰면 그 AI 직원(6장)이 BookOasis MCP(서재)·기본 도구(시각·날씨·웹 페이지)·추가 MCP로 찾아 답함 (모델이 도구 호출을 지원해야 함) |

### 기본 도구 · 추가 MCP

질문하기는 서재 질문뿐 아니라 일반 질문에도 답합니다. 쓸 수 있는 도구는 세 갈래입니다.

| 도구 | 설정 | 내용 |
|---|---|---|
| BookOasis MCP | `LIB3D_MCP_COMMAND` | 서재 데이터 (읽기 전용 도구만) |
| 기본 도구 | `LIB3D_AI_BUILTIN` (기본 켜짐) | `now` 지금 날짜·시각·요일, `weather` 날씨(Open-Meteo, 키 없음 - 지금·오늘·내일), `fetch_url` 공개 웹 페이지 본문 읽기(사설·내부 주소는 막음) |
| 추가 MCP | `LIB3D_MCP_SERVERS` | 한 줄에 `이름 = 실행 명령` 또는 `이름 = https://주소`(Streamable HTTP). 도구 이름은 `이름__도구`로 붙고, **모든 도구(쓰기 포함)를 그대로** 씀 - 믿을 수 있는 서버만 |

추가 MCP 예 ([AI 설정]의 '추가 MCP 서버' 칸):

```text
fetch = uvx mcp-server-fetch
time = uvx mcp-server-time --local-timezone=Asia/Seoul
search = https://내-검색-mcp-주소/mcp
```

- 실행 명령은 이 프로그램이 도는 서버(도커면 컨테이너 안)에서 실행되므로, `uvx`·`npx` 같은 실행기가 거기 깔려 있어야 합니다.
- [MCP 연결 시험]을 누르면 서버마다 ✓(도구 목록) / ✗(실패 이유)가 나옵니다. 하나가 실패해도 나머지 도구로 답하고, 답 아래에 "연결 못 한 MCP"를 알려 줍니다.
- LLM 서버가 붐비거나(503) 한도에 걸리면(429) 2초·6초 쉬었다가 두 번 더 시도합니다. 그래도 안 되면 "LLM 서버가 지금 붐벼서 답하지 못했습니다"라고 나옵니다 - 이건 MCP 문제가 아니라 LLM(예: Gemini) 쪽 사정이라 잠시 뒤 다시 묻거나 LiteLLM에 대체 모델(fallback)을 설정하세요.

### BookOasis MCP 실행 명령

질문하기는 BookOasis에 들어 있는 MCP 서버(`tools/mcp_server.py`, stdio)를 이 프로그램이 직접 실행해서 씁니다. 쓰기·제안 도구는 붙이지 않습니다.

```text
# BookOasis가 같은 서버에 직접 설치돼 있으면
python3 /BookOasis경로/tools/mcp_server.py

# BookOasis가 도커 컨테이너(bookoasis)로 돌면
docker exec -i bookoasis python3 tools/mcp_server.py
```

- 이 프로그램 자체를 도커로 돌리면 컨테이너 안에서 `docker` 명령을 쓸 수 없는 경우가 많습니다. 그때는 이 프로그램을 서버에 직접 설치하거나, 컨테이너에 도커 소켓(`/var/run/docker.sock`)과 docker CLI를 넣어야 합니다.
- 입력한 뒤 **[MCP 연결 시험]** 을 눌러 "연결됨 - 쓸 수 있는 도구 N개"가 나오는지 확인하세요.

## 6. AI 직원 (사서 · 도슨트) · AI 손님

AI 설정(연결 방식·주소·모델)을 마치면 각 층 로비에 **AI 직원**이 나옵니다(일하러 간 층에서만 걸어 다니고, 다른 층에서는 제자리). 머리 위 청록색 이름표로 구분되고, 이때 원래 안내 데스크에 서 있던 사서 모형은 빠집니다.

| 직원 | 자리 | 부르는 말 | 혼자 하는 업무 (기본) |
|---|---|---|---|
| 한서윤 · 사서 | 안내 데스크 | `@사서` `@안내` `@ai` `@봇` | 오늘의 추천 도서(하루 1번, 로비 안내판에 걸기) · 서재 점검(6시간마다) |
| 이도윤 · 도슨트 | 로비 | `@도슨트` `@가이드` | 구역 순찰(2시간마다, 구역으로 걸어가 소개 멘트 연습) |

- **직원이 할 수 있는 행동 (월드 도구)**: `move_to` 걸어서 이동(안내 데스크·로비·입구·라운지·엘리베이터·서가 구역) · `say` 소리 내어 말하기(머리 위 말풍선 + 같은 층 채팅) · `point_at_book` 찾은 책이 있는 서가로 가서 노란 화살표로 가리키기 · `set_board` 로비 **소식판** 내용 바꾸기 · `remember` 기억하기. 여기에 AI 설정의 BookOasis MCP·기본 도구·추가 MCP를 함께 씁니다(관람자 응대 때는 위 4장처럼 줄어듦).
- **로비 소식판**: 직원이 건 내용(제목 + 줄)과 최근 활동 5개. 이용자와의 문답 내용은 소식판에 나오지 않고 "이용자 응대"로만 표시됩니다.
- **혼자 일하기(자율 업무)**: 이용자가 아무도 없어도 서버가 30초마다 살펴 때가 된 업무를 **한 번에 하나씩** 합니다. 결과는 활동 기록과 소식판에 남습니다. 하루 호출 한도를 다 쓰면 "다음으로 미뤘습니다"로 기록만 하고 넘어갑니다. 직원 기본 업무는 하루 대략 150회, 손님 방문까지 합치면 400~500회 안팎을 씁니다(모델·도구 사용량에 따라 다름).
- **기억**: 직원마다 `remember`로 남긴 메모(최근 것 몇 십 개)와, 이용자별 최근 문답 6개·취향 메모를 기억해 다음 대화에 씁니다.
- **AI 손님 3명**: 박지호(대학생 - 판타지·무협 완결작), 최민서(회사원 - 오디오북·추리), 김영수(은퇴한 교사 - 역사·고전, 처음 읽을 만화). 머리 위 **호박색** 이름표.
  - 정해진 주기(3~4시간)마다 입구로 들어와 → 관심 구역으로 걸어가 → 책을 찾거나 직원에게 묻고(`ask_staff`, 직원이 실제로 찾아 답하고 책을 가리킴) → 책 앞에서 살펴보고(`browse_book`) 한마디 → 기억해 두고 → 입구로 나갑니다.
  - 손님과 직원의 대화는 그 층 **채팅에 모두에게 공개**됩니다(손님은 AI라 귓속말이 필요 없음). 손님은 성인 서재를 보지 않습니다.
  - 방문 중일 때만, 방문한 층(일반 층)에만 보입니다. 행동 사이에 걸어갈 시간을 두어 한 번 방문은 1~2분쯤 걸립니다.
  - 진짜 이용자 몫을 남기려고, 오늘 호출을 한도의 **70% 넘게** 썼으면 손님은 오지 않습니다. 기본 주기면 손님 셋이 하루 약 20번 오고, 방문 한 번에 손님+직원 합쳐 10~15회 정도 부릅니다.
- **설정 (관리자)**: [3D 서재 > AI 직원]
  - 맨 위 **자율 업무** 켜기/끄기, 오늘 쓴 호출 수.
  - 직원마다 일하기 켜기/끄기(손님은 방문하기), 이름·직업·목표·성격·부르는 말(쉼표로)·자리, 쓸 수 있는 행동, 업무(제목·주기(분)·지시문·켜기)와 **[지금 실행]**.
  - **[기본값으로]** 은 직원·손님을 처음 상태로 되돌립니다. 최근 활동 기록과 직원 메모도 이 화면에서 봅니다.
- 저장 위치: 설정 `DATA_DIR/lib3d_agents.json`, 상태(위치·말·기억·활동 기록·안내판) `DATA_DIR/lib3d_agents_state.json`, 하루 호출 수 `DATA_DIR/lib3d_ai_budget.json`.

## 7. 브런치 연재 낭독 코너 (1층 입구 오른쪽)

1층에 들어서면 입구 오른쪽에 **"브런치 연재 낭독"** 간판, 낭독대와 엘프 낭독가, 듣는 의자 두 개, 안내 화면이 있습니다.
브런치(brunch.co.kr)의 요일별 브런치북 연재를 골라 소리 내어 읽어 줍니다. ([ym_brunch](https://github.com/yume-script/ym_brunch) 플러그인과 같은 방식)

- **안내 화면**: 오늘 요일 연재 중 새로 올라온 회차 수와 제목(**NEW**). 10분마다 새로 받습니다. 낭독 중에는 "지금 낭독 중" 글이 위에 나옵니다.
- **안내 화면이나 낭독대를 누르면** 오른쪽에 패널이 열립니다.
  - 요일 탭(월~일·완결, 처음엔 오늘)과 탭마다 새 글 수, 최신순 목록(표지·회차 제목·브런치북·작가·몇 분 전·요약), [더 보기]로 20개씩.
  - 글을 누르면 본문(사진·인용 포함)과 이전 화/다음 화, [브런치 원문 ↗].
- **낭독**: [▶ 낭독] / [❚❚ 일시정지] / [■]. 읽는 문단이 노랗게 표시되며 따라 내려가고, 문단을 누르면 거기서부터 읽습니다.
  - 속도 0.8~2.0x, 목소리, **다음 화 이어서**(이 글을 다 읽으면 같은 브런치북 다음 화를 자동으로). 고른 값은 이 브라우저에 기억됩니다.
  - 읽는 문장은 **엘프 낭독가 머리 위 말풍선**에도 뜹니다. 패널을 닫아도 낭독은 계속되니, 서재를 걸어 다니며 들을 수 있습니다(■로 멈춤).
  - 소리는 **고른 사람의 브라우저에서만** 납니다(다른 사람에게는 들리지 않음). 관람자 계정도 쓸 수 있습니다.
- **목소리**
  - 브라우저 음성: 기기에 깔린 한국어 음성(보통 1~2개). 따로 설치할 것 없음.
  - Edge 음성(서버, 선택): 이 프로그램을 돌리는 파이썬에 `edge-tts`를 설치하고 재시작하면 선히·인준·현수 등 14개가 목록에 생깁니다(키·요금 없음, 마이크로소프트 Edge "소리 내어 읽기"의 비공식 경로, 서버에서 `speech.platform.bing.com`으로 나가는 인터넷 필요). 있으면 선히가 기본입니다.
- **edge-tts 설치** - 서비스가 쓰는 파이썬에 넣어야 합니다. 먼저 `systemctl cat bookoasis_assistant | grep ExecStart`로 확인:
  - `…/venv/bin/python …`이면 그 venv에: `/mnt/bookoasis_assistant/venv/bin/pip install edge-tts` 후 `systemctl restart bookoasis_assistant`
  - `/usr/bin/python3 …`(시스템 파이썬)이면 우분투 24.04·데비안 12는 `pip install`이 `externally-managed-environment`로 막힙니다. 둘 중 하나:
    - (권장) venv 만들기: `cd /mnt/bookoasis_assistant && python3 -m venv venv && venv/bin/pip install -r requirements.txt edge-tts` (venv가 없다는 오류면 `apt install python3-venv`), 서비스의 `ExecStart=`를 `/mnt/bookoasis_assistant/venv/bin/python /mnt/bookoasis_assistant/app.py`로 바꾸고 `systemctl daemon-reload && systemctl restart bookoasis_assistant`
    - 간단히: `pip install --break-system-packages edge-tts` 후 재시작 (시스템 파이썬에 직접 넣음)
  - 확인: 낭독 패널 목소리 목록에 "Edge 음성 (서버)" 묶음(선히·인준·현수 …)이 보이면 성공. "서버에 edge-tts가 없습니다"가 보이면 다른 파이썬에 설치된 것입니다.
- 끄기: `.env`에 `LIB3D_BRUNCH=false` 후 재시작하면 코너를 짓지 않습니다.
- 브런치 화면용 비공식 API를 쓰므로 브런치가 바뀌면 목록·본문이 안 나올 수 있습니다. 멤버십(유료) 글은 앞부분만 나옵니다.
- 서버는 `api.brunch.co.kr`·`brunch.co.kr`에 접속할 수 있어야 합니다. 목록은 5분, 글은 10분, Edge 음성은 30MB까지 메모리에 보관합니다.

## 8. 자주 막히는 곳

| 증상 | 확인할 것 |
|---|---|
| "BookOasis 3D 서재가 꺼져 있습니다" | `.env`에 `LIB3D_ENABLED=true` 후 다시 시작 |
| "BookOasis 보관함을 읽지 못했습니다" | `BOOKOASIS_DB_URL`·`BOOKOASIS_DB_TYPES`, DB 계정 권한, 이 서버에서 DB 접속 가능한지 |
| 표지가 색 상자·제목 표지로만 나옴 | `BOOKOASIS_URL`이 이 서버에서 열리는지 (`/covers/…`), BookOasis에 표지가 있는지 |
| 작품 상세·BookOasis 뷰어가 안 열림 | 브라우저에서 열리는 주소를 `LIB3D_PUBLIC_URL`에 |
| 여기서 읽기에서 쪽이 안 나옴 | 쪽에 이유가 적힘. 대개 `books.file_path` 경로를 이 서버에서 볼 수 없음 (같은 경로로 마운트) |
| "3D 라이브러리(three.js)를 불러오지 못했습니다" | 브라우저가 cdnjs.cloudflare.com·cdn.jsdelivr.net에 접속 가능한지 |
| 사람이 공·원통 모양으로만 나옴 | 사람 모형(jsdelivr)을 아직 받는 중이거나 못 받음 - 브라우저 콘솔의 `3D 서재 사람 모형` 메시지 |
| 화면이 버벅임 | [3D 모형]을 "지금 그대로"로, [인물 수]를 줄이기, 브라우저 하드웨어 가속 켜기 |
| AI: "API 키가 맞지 않습니다" / "연결하지 못했습니다" | API 주소 끝이 `/v1`까지인지, 키, 게이트웨이에 모델 이름이 있는지 |
| AI 직원이 안 보임 | AI 설정에 연결 방식·주소·모델이 들어 있는지, [AI 직원]에서 일하기가 켜져 있는지 |
| 낭독 코너 목록이 "브런치에서 가져오지 못했습니다" | 서버에서 `https://api.brunch.co.kr` 접속, 브런치 쪽 변경 여부 |
| 낭독 버튼이 눌리지 않음 / 목소리가 없음 | 브라우저에 한국어 음성이 있는지, 또는 서버에 `edge-tts` 설치 후 재시작 |
| "오늘 AI 호출 한도를 다 썼습니다" | [AI 설정]의 하루 호출 한도(`LIB3D_AI_DAILY`)를 늘리거나 다음 날까지 기다리기 |
| 질문하기가 도구를 안 씀 | 모델이 도구 호출(function calling)을 지원하는지, [MCP 연결 시험] 결과 |
